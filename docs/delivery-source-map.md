# Delivery Source Map

This workshop uses Microsoft LevelUp, VBD, Microsoft Learn, Copilot Camp, and public sample guidance as source material. Internal sources should inform framing and delivery mechanics; customer-shareable citations should come from public Microsoft Learn or public GitHub where possible.

## Delivery principles synthesized from source material

1. Lead with the healthcare workflow, not a product tour.
2. Build one evolving agent across the workshop rather than disconnected demos.
3. Treat governance as architecture, not as a final review slide.
4. Show failure modes intentionally: retrieval gaps, tool denial, policy rejection, human approval stop, and quality regression.
5. Make observability prove trust: effectiveness, health, adoption, cost/value, and governance/trust.
6. Keep all hands-on assets synthetic and PHI-free.

## Workshop storyline

Day 1: Build the agent.

Day 2: Earn the right to trust it.

The customer narrative is:

1. What healthcare workflow are we improving?
2. What can the agent know?
3. What can the agent do?
4. Under whose identity and policy does it operate?
5. Which decisions require a human?
6. How do we prove it remains safe, grounded, reliable, and valuable?
